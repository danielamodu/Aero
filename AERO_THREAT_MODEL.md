# Aero Threat Model

**Status date:** 2026-10-21  
**Scope:** current Next.js app, waitlist/admin backend, Fuji contracts and deployment scripts, plus the intended Send/Pay/Earn evolution. This is a source-based threat model, not a penetration test, contract audit, deployment attestation, or incident review.

## System context and trust boundaries

```text
User / browser
  ├─ wallet connector ── user-controlled wallet key and signing prompt
  ├─ HTTPS ── Next.js pages and waitlist/admin API
  │               ├─ optional Neon or local JSONL (waitlist only)
  │               └─ Resend (waitlist email)
  └─ public RPC ── Avalanche Fuji ── Aero sandbox contracts / tUSDC
```

Trust boundaries: (1) browser and its dependencies versus user wallet; (2) client and server/API; (3) app server and database/file/email providers; (4) browser/RPC observations versus chain state; (5) wallet-signed calls versus contract code and contract owner; (6) current testnet sandbox versus any future production system. There is no consumer financial API or ledger boundary today. Wallet connection establishes an address connection, not Aero authentication.

## Assets and actors

**Assets:** wallet private keys and signing authority; user test tokens and any future real assets; contract balances/shares and owner controls; handle registry state; transaction intent/receipt/history; waitlist email and requested handle; admin credentials/session; deployment keys/configuration; database and email provider credentials; availability and integrity of app/RPC data.

**Actors:** legitimate users; phishers and wallet drainers; malicious or compromised dependency/provider; abusive API clients; compromised admin/deployer; malicious recipient/token/adapter; compromised RPC/indexer/email/biller; accidental operator; opportunistic denial-of-service actor.

## Threat register

Likelihood: **High / Medium / Low / Unknown** describes the current exposure given repository evidence, not a measured incident rate. Severity: **Critical / High / Medium**. “Source verified” means the relevant code path or absence was observed in the repository; it does not prove exploitation or deployed behavior. Recommendations are proposed controls, not implemented controls.

## Evidence and residual risks

- **Source-verified gaps, not proven exploits:** no consumer auth, durable financial ledger, biller integration, verified live market integration, production deployment manifest, migrations, or consumer recovery flow was found. These absences make corresponding production claims unsafe.
- **Specific audit findings:** current admin auth and waitlist secret fallback, bounded/local activity history, unlimited approval path, no withdrawal queue/reserve, and incomplete operational controls are recorded in `AERO_SYSTEM_GAP_REGISTER.md`. Treat the report as source evidence, not a substitute for a live security test.
- **Yield review caveat:** the untracked B2.1.2 independent review in the working tree flags an asset-decimal/virtual-share concern and says a market fork test was not run. This model records it as an unverified high-severity concern requiring technical follow-up, not as a proven exploit.
- **Release residual risk:** M0 fails all production and beta releases closed. Testnet users still authorize actual Fuji transactions; mistaken or malicious signatures can lose test tokens. The release script validates declared configuration and a source allowlist; it does not query a live RPC to independently attest deployed bytecode. That verification remains a production gate.

No critical vulnerability exploitation was attempted in this milestone. No production incident or deployed contract was independently examined.
